    Peripherals¶

    The Jumpmind Commerce Point of Sale will interact with several peripheral devices that will provide the expected retail experience.

    Cash Drawer (attached through printer)¶

    This would be the physical drawer the cash till resides during business operations that responds directly to the register device through the printer.

    Action Field Option
    Cash drawer enabled cashDrawerEnabled True/False
    Cash drawer name cashDrawerName ex. HpEngageCashDrawer
    Cash drawer timeout cashDrawerTimeout ex. 3600000

    Cash Drawer (attached through device)¶

    This would be the physical drawer the cash till resides during business operations that responds directly to the register device.

    To determine weather the Cash Drawer will use EscP or JavaPOS, you first need to determine how it is connected to the device. If the connection is proprietary to the vendor (a non-standard usb style plugin), it is recommended to use JavaPOS. Otherwise, it is always recommended to start with EscP. Once you have determined the type of connector, and the recommended method of communication, you then need to identify the settings associated with the hardware brand and connection method. In the JMC base code, in the headless/point-of-sale/server/src/main/resources/application.yml file, there is a section titled DOC__cashDrawers. This will have most of the pre-configured, base use cases for different setups that have been commonly used. This is where you will use the information about how your Cash Drawer is connected to determine the settings needed in your application-xxxx.yml(e.g. application-fixed.yml, application-businessunit.yml) file.

    Customer Display¶

    A version of the Commerce app runs on device(s) that are setup to allow for customer interaction - displaying prices, confirming information.

    The devices running the customer display can also be picked up and used for line busting checkout if needed.

    Customer link loyalty enabled customerLinkLoyaltyEnabled True/False
    Customer send loyalty result to POS customerSendLoyaltyResultsToPos True/False
    Customer loyalty rewards select enabled customerLoyaltyRewardSelectEnabled True/False
    Customer link loyalty possible empty search criteria customerLinkLoyaltyPossibleEmptySearchCriteria True/False
    Customer charity select enabled customerCharitySelectEnabled True/False
    Select customer sell item builder sellItemBuilder customerDisplaySellItemBuilder
    Select customer lookup results builder customerLookupResultsBuilder customerLookupResultsBuilder
    Customer display rewards button enabled customerDisplayRewardsButtonEnabled True/False
    Is filter and search enabled isFilterAndSearchEnabled True/False
    Is customer item history tab enabled customerItemHistoryTabEnabled True/False
    Customer display viewer enabled enabled True/False
    Enter customer display appID appId customerdisplay
    Enter the customer display URL customerDisplayUrl
    Enter in customer display protocol customerDisplayProtocol http
    Enter in customer display port customerDisplayPort 7400

    MSR¶

    Jumpmind interacts with magnetic stripe readers that allow employees the option to swipe a security card to access the Commerce POS.

    Payment Devices¶

    Jumpmind Commerce supports the payment solutions from NCR Common Client, Ayden, ACI and Aurus as well as the devicea supported by those providers.

    Pole Display¶

    A pole display, or customer display, allows increased customer interaction. It provides a detailed display of the transaction as well as the ability to confirm or add information. These can take the form of a customer facing tablet, credit payment device, etc.

    Action Field Option
    Pole display enabled enabled True/False
    Port name portName ex. COM8
    Connection Class connectionClass ex. org.jumpmind.pos.print.RS232JSerialCommConnectionFactory

    As a note, ensure that you have included application-pole-display.yml in the desired service.conf file (e.g. fixed_service.conf) so messages will be displayed.

    Printer (Epson, Toshiba, Brother, NCR, etc.)¶

    Almost any brand of receipt printer is supported by Jumpmind commerce.
    The selected printed just needs to be configured for use.

    For POS reports, the default printer connected to the register will print these.

    Configuration depends on printer make and connection option.

    Action Field Option
    Service Class serviceClass ex. org.jumpmind.pos.print.EscpPOSPrinter
    Connection Class connectionClass ex. org.jumpmind.pos.print.UsbConnectionFactory
    Printer Command Locations printerCommandLocations ex. esc_p.properties,toshiba_esc_p.properties
    Print width printWidth ex. 42
    USB vendor ID usbVendorId ex. 0x08A6 #TOSHIBA
    USB product ID usbProductId ANY
    Host name hostName ex. 192.168.1.47
    Port port ex. 9100

    Vision Scanner (iOS Camera-Based)¶

    The Vision Scanner uses the device's native camera for barcode scanning on iOS devices. This scanner does not require external hardware or license keys.

    Action Field Option
    Vision scanner enabled enabled True/False

    Configuration: 

    openpos:
  plugins:
    VisionScanner:
      enabled: true  # Default: false

    JavaPOS Peripherals¶

    When using JavaPOS, you will need to ensure that you are using the hardware vendor’s JavaPOS libraries. It is recommended to modify the TTTT_service.conf file, replacing the TTTT with the deployment type (fixed, businessunit, etc.), to point to where the libraries needed are. For example, you would add a line like the following to the top of the fixed_service.conf file:

    wrapper.java.classpath.8=C:\POS\JavaPOS\LIB\*

    This would then have the fixed service look for the libraries for this hardware in the specified directory. When doing this, you will also need to add the following line in the same fooile:

    wrapper.java.additional.31=-Djava.library.path=C:/POS/JavaPOS/Lib/

    This is to ensure everything is pulled in when running the application/starting the service. Once that is done, you will need to modify the jpos.xml, found in the jmc/point-of-sale/conf directory, to have all relevant JavaPOS devices. If your cash drawer is daisy chained through your printer, you will need an entry for the cash drawer in here as well. These can either be made from scratch, or can be generated by using applications supplied by the hardware vendor.

    EscP and JavaPOS Interactions¶

    When using any peripherals, it is important to know how they interact with one another. That becomes more visible when working with peripherals that use different communication protocols. When using JMC, it is important to note that the communication protocols have precise interactions with one another, and can only be used in certain ways. If your cash drawer is daisy-chained through your printer, this means the cash drawer can only use the same communication protocol that the printer is using. If your printer is EscP, the cash drawer must use EscP, and the same is true for JavaPOS.
